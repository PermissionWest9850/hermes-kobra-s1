## Limits and remaining risks

- The dated npm audit lists 8 vulnerable package entries (5 high, 2 moderate,
  1 low). Stdio/no public listener is usage context, not blanket non-exploitability.
- Local integrity records detect changes relative to a baseline; they are not
  signatures and cannot defeat malicious replacement of both files and record.
  Legacy installations lack a trusted historical content baseline.
- Conversion-filter refusal is conservative: even an unused configured driver
  prevents patch verification. Doctor/reruns never remove or repair that config.
  Global/system Git configuration is deliberately not used for these checks.
- Missing PyYAML in the diagnostic interpreter yields NOT VERIFIED for YAML
  checks. No installation occurs to make the Doctor pass.
- Build/executable/profile presence is not a runtime/slicing/physical-feed test.
  Absent explicit identity/mapping evidence is NOT VERIFIED, not guessed.
- npm 12 warned about blocked esbuild postinstall; build and stdio succeeded on
  this host, not on a freshly validated distribution matrix.
- Git ignores prevent normal accidental additions, not `git add -f` or secrets
  embedded in otherwise public files. Pre-commit staged review/scanning remains
  required after a separately authorized future commit request.
- The original upload filename pre-check is not remotely atomic against another
  uploading client. Upload and print start remain separate explicit approvals.
